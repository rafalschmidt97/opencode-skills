# Daily Planner

Read calendar events and build a structured daily note with schedule, meeting links, and vault connections.

## Before Starting

1. **Check AGENTS.md** for calendar configuration:
   - Calendar provider (google, microsoft365, icloud)
   - Calendar ID (for Google: usually primary email)
   - Auth method (gcloud ADC for Google, az CLI for Microsoft)
   - Timezone
   - People directory path in vault
   - Meetings directory path in vault
   - Daily notes path in vault

2. **Determine the target date.** Default: today. User can specify another date.

3. **Check if a daily note already exists** for that date. If yes, update it (merge calendar events). If no, create it.

---

## Data Gathering

### Step 1: Fetch Calendar Events

Use the appropriate script/API based on the configured provider.

**For Google Calendar:** Use `scripts/gcal_events.sh` which calls the Calendar API via gcloud ADC.

**For Microsoft 365:** Use Microsoft Graph API via `az rest` or similar.

**For iCloud:** Parse exported .ics files from a configured path (iCloud doesn't have a direct API for agents).

Extract for each event:
- **Title** (summary)
- **Start time / End time**
- **Duration**
- **Location** (room name, if any)
- **Conference link** (Zoom, Teams, Meet — from `conferenceData` or description)
- **Description** (meeting agenda/notes if set)
- **Attendees** (names and response status)
- **Organizer**
- **Recurrence** (is this a recurring meeting?)
- **Your response status** (accepted, tentative, declined)

### Step 2: Match Events to Vault Entities

For each calendar event:

1. **Match to a meeting profile**: Check if the meeting title matches any meeting entity in the vault's meetings directory (fuzzy match on folder name or note title).

2. **Match to a person** (for 1:1s): If the event has exactly 2 attendees (you + one other), match the other person against vault person profiles by name or email.

3. **Check for existing call notes**: Look for call notes with today's date in the matched person/meeting folder.

### Step 3: Build Daily Note Schedule Section

Generate a `## Schedule` section (or update existing one) with a structured entry per event:

```markdown
## Schedule

### 09:00 — 09:30 | 1:1 with [[Person Name]]
- **Link**: [Join Zoom](https://zoom.us/j/...)
- **Room**: Room 4.12
- **Status**: ✅ Accepted
- **Prep**: [[Person Name#Since Last Time]] | [Board](board-url)
- **Notes**: 
- **Call note**: [[2026-05-27 09-00 Person Name 1-1]]

---

### 10:00 — 11:00 | [[Team Standup]]
- **Link**: [Join Meet](https://meet.google.com/...)
- **Attendees**: Person A, Person B, Person C (6 total)
- **Status**: ✅ Accepted
- **Notes**: 
- **Call note**: —

---

### 14:00 — 14:30 | External: Client Review
- **Link**: [Join Teams](https://teams.microsoft.com/...)
- **Status**: ⏳ Tentative
- **Notes**: 
```

### Formatting Rules

| Element | Format |
|---------|--------|
| Time | `HH:MM — HH:MM` (24h, local timezone) |
| 1:1 meetings | Link to person profile: `[[Person Name]]` |
| Recurring meetings | Link to meeting profile: `[[Meeting Name]]` |
| Declined events | Show but mark with ❌ and collapse |
| All-day events | Separate section at top: `## All-Day` |
| Conference links | Clickable markdown links with provider name |
| Free/gap time | Optionally note gaps > 30min for focus blocks |

### Step 4: Link Call Notes

For each event matched to a person or meeting:
- Check if a call note already exists for today in that entity's folder
- If yes: link it with `[[filename]]`
- If no: show `—` (the user creates notes during/after meetings)

The daily note's existing Bases block (`## Calls Today`) already aggregates call notes by date, so this is supplementary — the schedule gives time-ordered context while Bases gives the note list.

## Daily Note Structure

The skill expects/creates daily notes with this structure:

```markdown
---
tags:
  - daily
date: YYYY-MM-DD
---

## Schedule

(generated by this skill — calendar events with links and spaces for notes)

## Tasks

- [ ] task items (user-managed)

## Notes

(freeform notes for the day)

## Calls Today

` ` `base
filters:
  and:
    - note.tags == "call"
    - note.date == this.note.date
views:
  - type: table
    name: Calls
    sort:
      - property: file.name
        direction: ASC
` ` `
```

If the daily note already exists:
- Insert/update only the `## Schedule` section
- Preserve all other sections (Tasks, Notes, Calls Today)
- Never overwrite user content

---

## Interactive Mode

When the user is reviewing their day:
- Highlight meetings that need prep (1:1s where recent call notes have open action items)
- Flag conflicts (overlapping events)
- Suggest which meetings might need a call note created
- Offer to create blank call notes for upcoming meetings

---

## Batch Mode

When populating multiple days (e.g., "fill in my week"):
- Process each day sequentially
- Create/update daily notes for each day
- Report: N days populated, M events total, K matched to vault entities

---

## Post-Meeting Updates

After a meeting, if the user says "log [meeting name]" or "create note for [meeting]":
- Create a call note in the appropriate vault folder
- Use the calendar event metadata for frontmatter (date, time, person/meeting)
- Link it back from the daily note schedule entry

---

## Configuration

The skill reads these from AGENTS.md:

```markdown
## Daily Planner Configuration

- **Calendar provider**: google | microsoft365 | icloud
- **Calendar ID**: user@company.com (or 'primary')
- **Timezone**: Europe/Warsaw
- **Quota project**: project-id (Google only, for API quota routing)
- **People directory**: areas/{context}/people/
- **Meetings directory**: areas/{context}/meetings/
- **Daily notes path**: daily/
- **Working hours**: 08:00-18:00 (for gap detection)
- **Declined events**: show | hide
- **Focus blocks**: true | false (highlight gaps > 30min)
```

See `references/calendar-setup.md` for provider-specific setup instructions.
